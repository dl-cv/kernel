# GD32 I2C 设备接入

## 功能概述

本次将鲁班猫 RK3588 `i2c1` 总线上的 `GD32@0x2a` 从“仅能被 `i2cdetect` 看到应答”的状态，提升为**由 Linux 设备模型正式实例化并绑定最小驱动**的 I2C 设备。

本次接入只解决“正式识别与内核接管”问题，不实现 GD32 的具体寄存器协议、触发命令或版本查询逻辑。

## 背景与目标

板端已有证据表明 `i2c1` 的 `0x2a` 地址存在 ACK，但板级 DTS 中没有对应节点，内核源码中也没有现成的 `GD32` I2C 驱动。因此：

- `GD32` 只能被用户态当作“总线上有响应的未知地址”看待。
- 内核不会为其建立稳定的 board-described `i2c_client`。
- `IMX296` 相关链路若需要把 `GD32` 作为辅助 MCU 使用，缺少正式的设备入口。

本次目标：

- 在 `i2c1` 下补 `gd32-mcu@2a` 设备树节点。
- 增加一个最小 `gd32-mcu` I2C 占位驱动并完成 `probe`。
- 在鲁班猫默认 `defconfig` 中使能该驱动。
- 与 `cam1-imx296 overlay` 关联，只有启用 IMX296 方案时才打开该节点。

## 功能边界

- 仅覆盖 `rk3588-lubancat-5io` 的 `i2c1` 总线。
- 仅处理 `GD32@0x2a` 的正式设备接入。
- 不臆造 GD32 内部寄存器地址、位定义和命令协议。
- 不实现字符设备、ioctl、自定义 sysfs 寄存器访问接口。
- 不替代后续真正的 GD32 功能驱动开发。

## 架构概览

当前接入关系如下：

1. `rk3588-lubancat-5io-csi.dtsi` 在 `&i2c1` 下提供 `gd32_mcu: gd32-mcu@2a` 模板节点，默认 `disabled`。
2. `rk3588-lubancat-5io-cam1-imx296-overlay.dts` 在启用 IMX296 时同时把 `&gd32_mcu` 置为 `okay`。
3. Kernel 启动后，I2C core 根据设备树实例化 `1-002a`。
4. `drivers/misc/gd32_mcu.c` 依据 `compatible = "gd,gd32-mcu"` 完成最小 `probe`，把该地址正式纳入内核管理。

## 调用关系

1. U-Boot 叠加 `rk3588-lubancat-5io-cam1-imx296-overlay.dtbo`。
2. Overlay 将 `&gd32_mcu` 置为 `status = "okay"`。
3. Kernel 启动后，I2C core 在 `i2c1` 上实例化 `gd32-mcu@2a`。
4. `gd32_mcu_driver` 根据 `compatible = "gd,gd32-mcu"` 匹配该节点。
5. `gd32_mcu_probe()` 通过最小功能检查并打印绑定日志。

## 配置说明

- 宿主机环境：Linux
- 交叉工具链：`aarch64-linux-gnu-`
- 目标架构：`arm64`
- 目标板：`rk3588-lubancat-5io`
- 默认配置：`CONFIG_GD32_MCU=y`
- 设备树节点：`gd32_mcu: gd32-mcu@2a`
- 设备地址：`0x2a`

## 编译与部署

### 宿主机最小编译验证

```sh
make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- lubancat_linux_rk3588_defconfig
make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- -j8 \
  drivers/misc/gd32_mcu.o \
  rockchip/rk3588-lubancat-5io.dtb \
  rockchip/overlay/rk3588-lubancat-5io-cam1-imx296-overlay.dtbo
```

### 板端部署关注点

- 若板端通过 `uEnvLubanCat5IO.txt` 启用 IMX296 overlay，则 `GD32` 节点会一起被启用。
- 若未启用该 overlay，`gd32_mcu` 默认不会被内核实例化。

## 运行链路

1. 板端加载 IMX296 overlay。
2. `gd32_mcu@2a` 节点被置为 `okay`。
3. I2C core 建立 `1-002a` 设备。
4. `gd32-mcu` 驱动完成 `probe`。
5. 后续若需要真正访问 GD32 协议，再在该驱动上继续扩展。

## 风险点

- 当前驱动只是占位驱动，无法直接替代真实业务协议驱动。
- 若后续需要继续使用 `i2c-tools` 直接访问 `0x2a`，需要确认驱动绑定后的用户态访问方式。
- `GD32` 当前通过 IMX296 overlay 联动启用；如果后续希望脱离 IMX296 单独启用，需要再拆分 overlay 或增加独立入口。
- 如果板端硬件上未接入该 MCU，而误启用了 overlay，仍可能出现“设备节点存在但功能不可用”的现象。
