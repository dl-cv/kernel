## 功能概述

本次适配面向 `rk3588-lubancat-5io` 的 `cam1` 槽位，目标是让 IMX296 具备“默认可编译、overlay 可加载、板端具备启用入口，并且 media graph 结构与 cam1 现有模板体系一致，同时可通过 `GPIO1_D6(PWM14_M2)` 输出低电平单脉冲触发”的最小可用集。

## 背景与目标

在本次修改前，仓库中已经有 `drivers/media/i2c/imx296.c` 和 `rk3588-lubancat-5io-cam1-imx296-overlay.dts`，但默认 `defconfig` 未启用 `VIDEO_IMX296`，`uEnv` 也未提供 IMX296 的注释入口。进一步板端日志还出现 `rkcif_update_sensor_info` / `Not active sensor`，说明原 overlay 通过动态创建 `imx296@1a` 并重写 `csi2_dcphy1/port@0` 的方式，存在 media graph 组织风险。最小编译验证过程中还暴露出驱动自身缺少头文件和前向声明的问题。完成 graph 修复后，板端仍出现 `rockchip-csi2-dphy0: No pixel rate control in subdev`，结合 Rockchip DPHY 代码可确认其真实依赖的是 `V4L2_CID_LINK_FREQ`，而旧版 `imx296.c` 只注册了 `PIXEL_RATE`，没有向接收端暴露固定 lane 速率。补齐 `LINK_FREQ` 后，板端进一步暴露 `imx296 1-001a: supply ovdd not found, using dummy regulator`，根因是 `dcphy1_imx296` 节点把 IO 电源写成了 `dovdd-supply`，与驱动要求的 `ovdd-supply` 名称不一致。修正 `ovdd-supply` 后，板端在默认 autosuspend 路径下还出现 `8-bit write to 0x3005 failed: -6`，而把 `power/control` 强制设为 `on` 后该错误消失，说明 `runtime PM` 触发的上电恢复时序仍偏激进。

在上述基础问题梳理完成后，又确认 `GPIO1_D6` 已直接连接到摄像头 XTRIG 输入。当前硬件由 `RK3588 PWM14_M2` 输出单触发脉冲，并要求保留最小板端入口：空闲高、电平有效脉冲为低、当前板级默认宽度 `800us`、宽度可读可改、`echo 1` 可直接打一次单脉冲。

本次目标：

- 默认 `defconfig` 可带上 IMX296 驱动。
- `rk3588-lubancat-5io-csi.dtsi` 提供 IMX296 固定模板节点和 1-lane graph endpoint。
- `cam1-imx296 overlay` 改为模板启用模式，并可正常编译叠加到 `rk3588-lubancat-5io.dtb`。
- `imx296.c` 显式提供固定 `LINK_FREQ` 控件，满足 Rockchip CSI DPHY 的起流要求。
- `dcphy1_imx296` 的 `ovdd-supply` 与驱动 regulator 名保持一致，避免退回 dummy regulator。
- 经过原始/保守两套 `imx296_power_on()` 时序对比后，当前代码树已回退到原始短延时时序，并继续结合 `stream-state[...]` 关键寄存器读回日志区分是 `runtime PM` 边界问题，还是 sensor/MIPI 实际无有效出流。
- `imx296.c` 提供可通过 `echo` 写入的 `run_mode` 节点，用于在 `FREE_RUN` 与主模式快速触发之间切换，当前 5IO 默认上电即为 `master_fast_trigger`。
- 修复 `trigger-mode = <1>` 默认 `master_fast_trigger` 与 `V4L2_CID_IMX296_OP_MODE` 控件缓存默认 `free_run` 的脱节问题，避免首次写 `free_run` 被误判为 no-op。
- `GPIO1_D6(PWM14_M2)` 可作为 IMX296 触发输出，空闲高、触发低，当前默认低脉宽 `800us`。
- `imx296.c` 提供 `trigger` / `trigger_pulse_us` 两个 sysfs 节点，支持查看、修改脉宽并打一次单脉冲。
- `uEnv` 中有明确的 `cam1-imx296` 启用入口。
- `trigger-dev` 默认硬触发目标切换到 `IMX296`：`GPIO0_C6 -> trigger-dev -> /sys/bus/i2c/devices/1-001a/trigger`。
- `trigger-dev` 新增 `input_mode=button/edge` 双输入模式，当前 5IO 默认使用 `edge`，适合干净外部脉冲输入。
- 修复 RK GPIO V2 在 `trigger-dev` 从 `button` 运行时切到 `edge` 后仍误保留双沿中断的问题，确保 `GPIO0_C6(GPIO_ACTIVE_LOW)` 在 `edge` 模式下只响应下降沿。

## 功能边界

- 仅处理 `rk3588-lubancat-5io` 的 `cam1`。
- 不修改其它槽位的 sensor 选择逻辑。
- 不执行整包镜像烧录。
- 不直接验证真实板端采图链路。
- 不在本轮实现 `XMASTER=High` 的真正 slave/外触发模式。
- 不在本轮启用 `CONFIG_PWM_ROCKCHIP_ONESHOT`。
- 不处理 `cam1 IMX415` / `cam1 OS08A20` 与 `GPIO1_D6` 的并用场景。
- 不修改 `drivers/media/i2c/os08a20.c` 和 `cam1-os08a20` overlay 的现有 FSIN 方案。

## 架构与模块关系

`rk3588-lubancat-5io-csi.dtsi` 负责提供 `cam1` 的公共 CSI 拓扑、Rockchip ISP/CIF 链路，以及 IMX296 的固定模板节点和 1-lane graph endpoint。

`rk3588-lubancat-5io-cam1-imx296-overlay.dts` 负责：

- 只开启 `&i2c1`，不再动态创建 `imx296@1a`。
- 将 `&dcphy1_imx296` 置为 `status = "okay"`。
- 使能 `mipi1_csi2`、`rkcif_mipi_lvds1`、`rkisp1`、`rkisp1_vir0`。
- 使能 `&pwm14`，并将其 pinmux 切到 `&pwm14m2_pins`，把 `GPIO1_D6` 复用为 PWM 输出。
- 显式将 `&dcphy1_imx415` 压为 `disabled`，避免同槽位两个传感器同时激活。

当前 IMX296 节点默认保留 `rockchip,camera-module-sync-mode = "internal_master"`，并把 `trigger-mode = <1>` 作为当前 5IO 的默认上电模式，使其开机即进入 `master_fast_trigger`；同时新增 `pwm-names = "trigger"`、`pwms = <&pwm14 ... PWM_POLARITY_INVERTED>` 和 `rockchip,trigger-pulse-us = <800>`，把默认触发输出描述直接挂在 IMX296 节点上。

`rk3588-lubancat-5io-trigger-dev-overlay.dts` 当前默认输入口保持为 `GPIO0_C6`，`trigger-path` 已从 `OS08A20` 切换到 `IMX296` 的 `/sys/bus/i2c/devices/1-001a/trigger`，并新增 `trigger-input-mode = "edge"`、`IRQ_TYPE_EDGE_BOTH` 与 `debounce-ms = <10>`，用于让外部脉冲默认直接转发到 IMX296 单脉冲入口；若后续改接机械按键，可运行时切到 `input_mode=button`。由于 `GPIO0_C6` 当前配置为 `GPIO_ACTIVE_LOW`，`edge` 模式理论上只应响应下降沿，本次同时在 `drivers/gpio/gpio-rockchip.c` 修复了 RK GPIO V2 运行时切边沿时 `int_bothedge` 未清零导致的双沿残留问题。

说明：当前产品 **XTRIG 仅经 SoC**（`PWM14_M2` → 相机触发脚）；`gd32-mcu` 相关 DTS/驱动已从本树移除。

当前 `imx296.c` 还负责向上游媒体栈暴露：

- `PIXEL_RATE`，供 ISP/CIF 估算数据率。
- 固定的 `LINK_FREQ`，供 Rockchip CSI DPHY 配置 lane 速率。
- 当前回退为原始短延时 `power_on` 时序，用于继续对比 `runtime PM` 相关现象；`stream-state[...]` 日志用于补足软件侧证据。
- `run_mode` sysfs 节点，供板端通过 `echo` 切换 `FREE_RUN` / 主模式快速触发。
- `trigger` sysfs 节点，供板端通过 `echo 1` 输出一次低电平单脉冲。
- `trigger_pulse_us` sysfs 节点，供板端查看/修改触发低脉宽。

当前 `dcphy1_imx296` 节点的三路电源属性应为：

- `avdd-supply`
- `ovdd-supply`
- `dvdd-supply`

## 调用链分析

1. U-Boot 根据 `uEnvLubanCat5IO.txt` 读取 `dtoverlay` 条目。
2. 若启用 `rk3588-lubancat-5io-cam1-imx296-overlay.dtbo`，overlay 叠加到 `rk3588-lubancat-5io.dtb`，开启 `i2c1`、启用 `&dcphy1_imx296`、启用 `&pwm14` 并切到 `&pwm14m2_pins`，同时关闭 `&dcphy1_imx415`。
3. Kernel 启动后，I2C core 在 `i2c1` 上枚举 `compatible = "sony,imx296lq"` 的模板节点。
4. `imx296_probe()` 申请时钟、电源、GPIO、可选 `trigger` PWM，并注册 V4L2 子设备及其 `LINK_FREQ` / `PIXEL_RATE` 控件和 sysfs 调试入口。
5. Rockchip CSI DPHY 通过 `V4L2_CID_LINK_FREQ` 获取单 lane MIPI 速率，完成接收端配置。
6. Rockchip CIF/ISP 通过 `dcphy1_in_imx296 -> csi2_dcphy1 -> mipi1_csi2 -> rkcif_mipi_lvds1 -> rkisp1_vir0` 链路接入。
7. 当前 5IO 默认通过 `trigger-mode = <1>` 让 sensor 上电即进入 `master_fast_trigger`；`imx296_ctrls_init()` 会同步 `V4L2` 运行模式控件缓存到该默认值，避免首次写 `free_run` 被控件框架当作 no-op；板端仍可通过 `echo free_run > /sys/bus/i2c/devices/1-001a/run_mode` 或 `echo master_fast_trigger > /sys/bus/i2c/devices/1-001a/run_mode` 在两种模式间切换。
8. 板端通过 `echo 1 > /sys/bus/i2c/devices/1-001a/trigger` 让 `PWM14_M2` 立即输出一次低电平脉冲；脉宽由 `trigger_pulse_us` 决定，当前默认 `800us`。
9. 当前板端默认 `input_mode=edge`：`trigger-dev` 监听 `GPIO0_C6(GPIO_ACTIVE_LOW)` 的下降沿，并直接执行与步骤 8 等价的 sysfs 写入。
10. 若后续改接机械按键，可运行时切到 `input_mode=button`，通过双沿 + 防抖 + 状态机只在“按下”时转发一次触发。
11. 本次在 RK GPIO V2 上补充了 `int_bothedge` 清零逻辑，避免从 `button` 切到 `edge` 或默认 `edge` 运行时硬件仍继续上报上升沿中断，确保外部脉冲链路只复用下降沿。

## IMX296 外部触发快速定位

当前代码树中的 `IMX296` 外部触发不是单文件实现，而是 `sensor` 驱动、输入转发驱动和板级设备树共同构成的一条完整链路。若现场只想快速判断“脉冲有没有进来、有没有被转发、有没有真正打到相机”，优先看本节即可。

### 默认触发链路

```text
外部脉冲
  -> GPIO0_C6
  -> drivers/input/misc/trigger-dev.c
  -> /sys/bus/i2c/devices/1-001a/trigger
  -> drivers/media/i2c/imx296.c
  -> PWM14_M2(GPIO1_D6)
  -> IMX296 触发输入脚
```

| 环节 | 所在位置 | 作用 | 备注 |
| --- | --- | --- | --- |
| 外部输入口 | `rk3588-lubancat-5io-trigger-dev-overlay.dts` 的 `input-gpios = <&gpio0 RK_PC6 GPIO_ACTIVE_LOW>` | 接收板外触发沿 | 当前默认低有效，`edge` 模式下按下降沿工作 |
| 输入中断处理 | `trigger_dev_irq()` | 有效沿到来时排队一次触发 | 干净脉冲场景建议保持 `edge` |
| 转发写入 | `trigger_dev_write_once()` | 向 `trigger-path` 写入 `1\n` | 等价于手工 `echo 1 > /sys/bus/i2c/devices/1-001a/trigger` |
| 单次触发入口 | `trigger_store()` | 校验用户写入值并调用单次触发 helper | 当前仅接受 `1` |
| 脉冲输出 | `imx296_trigger_once_locked()` | 通过 `PWM14_M2` 输出一次低有效脉冲 | 空闲高、触发低 |

### 排查顺序

| 步骤 | 检查点 | 结论 |
| --- | --- | --- |
| 1 | `ls /sys/bus/i2c/devices/1-001a/` 是否存在 `run_mode` / `trigger` / `trigger_pulse_us` | 不存在说明 `imx296.c` 未成功 probe 或 IMX296 overlay 未生效 |
| 2 | `cat /sys/devices/platform/trigger-dev*/input_mode` 是否为 `edge` | 不一致时外部脉冲语义可能与预期不同 |
| 3 | 手工执行 `echo 1 > /sys/bus/i2c/devices/1-001a/trigger` 是否能看到触发日志 | 失败优先排查 `imx296.c` / PWM / DTS |
| 4 | 外部脉冲输入后 `stats` 的 `irq/ok/fail` 是否增长 | 不增长先看 `GPIO0_C6` 连线和 `trigger-dev` overlay |
| 5 | 即便脉冲已发出仍无单帧结果，检查 `run_mode` 是否为 `master_fast_trigger` | 当前方案依赖 fast trigger，而非 slave sync |

- `defconfig` 已补 `CONFIG_VIDEO_IMX296=y`

- `drivers/media/i2c/imx296.c` 已新增 `stream on` 前后关键寄存器读回日志，用于定位 sensor 是否真正进入输出态

## 风险点

- 合并后的 DT 中仍会保留 `dcphy1-imx415@1a` 这个 disabled 模板节点，因此 `dtc` 仍会报重复 unit-address 警告；这属于当前 vendor DTS 组织方式的已知现象，不等于两个 active 节点同时 probe。
- 真正是否能稳定出流，仍受硬件连线、电源时序、MIPI 1-lane 带宽、板端加载顺序影响。
- 当前 `imx296.c` 仍以 `internal_master` 为主路径，若后续恢复 `XMASTER=High` 的 slave/外触发方案，还需单独适配驱动与 DT。
- 主模式快速触发虽然已经可通过 `run_mode` 切换，但板级 `XMASTER` / 外部触发脉冲若不匹配，切换后仍可能看起来“黑屏”。
- 若板端仍运行未包含本次补丁的旧内核，首次 `echo free_run` 仍可能被控件缓存 no-op 吞掉，临时规避方式仍是先写一次 `master_fast_trigger` 再写 `free_run`。
- 本次 `LINK_FREQ` 修复只解决 Rockchip DPHY 速率查询缺口；若重新烧录后仍黑屏，就需要继续分层排查 sensor 实际出流、板端光路和应用打开节点是否正确。
- 本次 `ovdd-supply` 修复仅解决 DTS 属性名与驱动 regulator 名不一致的问题；若板端硬件实际没有提供正确的 IO 电源，仍可能继续黑屏。
- 当前已回退原始 `power_on` 时序，`0x3005`/`-ENXIO` 类边界问题可能重新出现；若在原始时序下仍保持 `stream-state[...]` 显示 sensor 已退出 `standby` 且 `test_pattern` 已生效、但 `frame dma end` 仍为 0，则主因更偏向 sensor/MIPI 输出层或板级 DPHY 接收。
- `GPIO1_D6/PWM14_M2` 与 `cam1 IMX415` overlay 的 `pwm14` 用法、`cam1 OS08A20` overlay 的 `fsin-gpios` 用法存在明确冲突，不能同时加载。
- 当前未启用 `CONFIG_PWM_ROCKCHIP_ONESHOT`，因此“命令到脉冲开始”的时延确定性不等同于专用 MCU 硬件定时单脉冲；当前方案更偏向最小可用和板端直控入口。
- trigger-dev 默认目标已切到 IMX296，若板端仍加载 OS08A20 触发路径习惯脚本（`1-0036/trigger`）会出现行为偏差，需统一部署脚本与 overlay 组合。
- `input_mode=edge` 仍会对机械按键回弹敏感，只建议在干净外部脉冲输入场景使用。
- 若板端仍在运行未包含本次 `gpio-rockchip` 修复的旧内核，即使 `input_mode=edge` 也可能继续表现为上升/下降沿都触发。

## 已知问题

- `rk3588-lubancat-5io-csi.dtsi` 顶部 `cam1` 链路注释与真实 endpoint 指向不一致，真实链路应为 `rkisp1_vir0`；该问题不影响本次最小修复，但会影响后续阅读体验。
